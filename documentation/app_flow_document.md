# FaceReader-AI App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new visitor arrives at the FaceReader-AI application, they first land on the home page found at the root URL. This page briefly introduces the face recognition concept and provides clear calls to action for creating an account or signing in. If the visitor clicks the sign-up button, they are taken to the sign-up page, where they enter their email address, choose a secure password, and confirm the password. After submitting the form, an account is created and the user is automatically logged in and redirected to the dashboard. Alternatively, if the visitor prefers to use a social login, they click one of the social icons displayed on the sign-up page, complete the third-party authentication flow, and then return to the dashboard just as with email sign-up. For returning users, the sign-in page prompts for email and password or offers social login as well. If a user has forgotten their password, a “Forgot Password” link on the sign-in page leads to a password recovery page. There, the user submits their email, receives a recovery link, clicks it to open a secure reset page, and sets a new password. Once signed in, the user’s session persists until they either manually sign out or the session expires. Signing out is done by clicking the sign-out button in the navigation area, which immediately ends the session and returns to the home page.

## Main Dashboard or Home Page
After logging in, users arrive at the main dashboard, which spans the full width of the screen. A vertical sidebar on the left offers navigation options such as Dashboard, Profile Settings, and Log Out, as well as a theme toggle switch for light or dark mode. At the top of the page, a header displays the application name and may show the user’s avatar or initials. The central area is filled with section cards that highlight various features, including interactive charts and data tables. The section cards can display sample data, analytics, or placeholders for future AI insights. From here, users can click on any card or link in the sidebar to visit a detailed view of that feature. The sidebar stays visible as users move between pages to ensure smooth navigation back to the dashboard.

## Detailed Feature Flows and Page Transitions
When a user clicks on one of the section cards, for example the interactive chart card, the application navigates to the chart page. This page shows a full-width chart component that users can hover over or click for detailed information. All data is fetched through client-side API calls to Next.js API routes, which return JSON data from the database. If a user instead selects the data table card, they go to a table page that loads a paginated table component. The table supports sorting and searching by columns. Search terms update the table through new API requests, and sorting triggers a re-fetch with the chosen order. To edit the user’s own profile, the user chooses Profile Settings from the sidebar. This opens a profile page with fields for name, email, and password. Users can change their display name by typing a new value and clicking the Save button. If they wish to update their password, they enter their current password, choose a new one, and confirm it before submitting. Each field update causes a server API call that returns success or fails with a message. Every time the application transitions between pages, it uses Next.js’s App Router to pre-fetch data for the next page, creating a smooth experience with minimal loading screens.

## Settings and Account Management
Within the Profile Settings page, users can update personal details such as their display name and email address. Changing the email requires a confirmation link sent to the new address. Password changes prompt for the current password first to protect the account. Below profile details, a section for theme and notification preferences lets users choose default light or dark mode and toggle email notifications on or off. These preferences are stored in the database and applied on each login. When the user finishes making changes, they click Save, and the page confirms the update with a brief success message. After saving or canceling, the user can simply click Dashboard in the sidebar to return to the main view.

## Error States and Alternate Paths
If a user enters an incorrect email or password on sign-in, the form displays an inline error message explaining which field is invalid. During sign-up, if the email is already in use or passwords do not match, similar messages appear directly under the relevant inputs. When the user tries to access the dashboard without a valid session, they are redirected to the sign-in page with a notification explaining that they must log in first. If the network connection drops while using the dashboard or a details page, a banner appears at the top of the screen warning of connectivity issues and offering a Retry button. API calls return clear error responses when validation fails or when the server experiences an issue, and these responses are shown to the user in plain language. If a user attempts an action they are not allowed to do, such as updating another user’s data, the server returns a forbidden error and the UI presents a message indicating insufficient permissions.

## Conclusion and Overall App Journey
A typical user journey begins with discovering the application’s landing page and signing up with their preferred method. After email confirmation, they sign in and arrive at the dashboard, where they quickly get an overview of available features. From the dashboard, they navigate to interactive charts or tables to view or analyze data. They manage their account and preferences in the profile settings area, adjusting their password, display name, theme choice, and notification options. Error messages guide them if something goes wrong, and the application gracefully recovers from connectivity interruptions. When the session ends or the user signs out, they return to the landing page. With this foundation, users can enjoy a secure, responsive experience from sign-up through everyday use of the FaceReader-AI platform.
